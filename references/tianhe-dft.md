# 天河作业提交与验收

这是一套适用于已授权天河账户的通用工作流；项目参数、科学方法和账号配额必须以当前任务及现场查询为准。

1. 用户完成 aTrust 登录；使用私人 profile、主机 pin 与已授权凭据建立连接。先核对远端 hostname、id -un 和工具可用性；连接成功不代表调度额度或软件环境可用。
2. 查询正在运行和等待的作业、关联账户的节点/CPU/提交任务限制、可用分区、时间上限与存储余量。共享账号下，节点数和运行加排队作业数是两个不同约束；同一团队的其他工作也计入。
3. 固定输入、源码版本、软件版本、批次脚本与 SHA256；科学计算与压力测试只在计算节点运行。项目的参数、收敛准则与结果路径要事先写入任务清单，未知方法不能假装来自论文或作者。
4. 先在计算节点用小规模任务核验依赖、内存、CPU 绑定、完整接受步、检查点和恢复过程；只有准入通过后才提交有界的正式批次。多样本尽量使用有界 allocation 内的任务队列，避免为每个样本和阶段堆积大量依赖作业；此架构仍需符合站点规则。
5. 仅提交一次并保存回执。若网络超时或提交结果不确定，先查询作业名、用户、时间、工作目录及调度记录，确认是否已提交后再决定，不重复盲试。排队不等于运行，获得 JobID 也不等于计算成功。
6. 动态释放已完成且经 PID、主机和调度身份核验的闲置节点时，保留控制节点及活跃工作进程。已分配节点数不能等同于 CPU 使用率；按实际任务数、线程数、内存与吞吐评估算力。
7. 结束后同时核验调度状态、退出码、日志摘要和每条任务的科学结果；区分数值收敛、物理约束可行、预算到期、错误及论文形态。保存完整可追溯检查点，确认续跑的参数、状态与预算后再恢复。

站点工具通常包括 yhbatch、yhrun、squeue、sacct 与 scontrol，但可用命令、队列规则和参数由站点配置决定；使用前先检查。密码连接 helper 仅负责只读检查，实际提交要走用户授权且能核验回执的项目控制器。
